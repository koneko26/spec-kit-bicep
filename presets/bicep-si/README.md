# Bicep SI Workflow (preset)

Tunes Spec Kit's core SDD workflow for **Azure-best-practice-first IaC built with Bicep**, and
lays out the numbered SI phase folders. Pairs with the **`bicep`** extension (which adds the
basic/detailed design and unit-test phases).

## What it changes (all by `append` — core is not replaced)

### Template overrides

| Template | Strategy | Effect |
|----------|----------|--------|
| `constitution-template` | append | Adds the "Azure best practice → Bicep" policy + WAF 5 pillars |
| `plan-template` | append | Bicep source-layout note + WAF Constitution Check gate |
| `spec-template` | append | Infra requirements: Functional / Non-Functional (9 categories aligned to WAF), Greenfield/Brownfield, env strategy |

### Command overrides

| Command | Strategy | Effect |
|---------|----------|--------|
| `speckit.constitution` | append | Records Azure-BP-first → Bicep policy + WAF 5 pillars as principles/gates |
| `speckit.specify` | append | Infra requirement viewpoints (functional/non-functional) + scaffolds `100_`–`700_` + `000_index.md` (A2) |
| `speckit.clarify` | append | Adds Azure-infra clarification dimensions (landing zone, regions, connectivity, identity, compliance, …) |
| `speckit.tasks` | append | Bicep WBS under `600_build/` + cross-cutting WAF tasks; construction-only; updates index |
| `speckit.analyze` | append | Consistency report + NF/WAF coverage matrix → `500_tasks/analysis-report.md`; updates index |
| `speckit.implement` | append | Construction only (no test execution); writes Bicep into `600_build/`; updates index |

`speckit.plan` is **not** overridden — `plan.md` is generated by `/speckit.bicep.detail-design`.

### WAF backbone

The Well-Architected Framework 5 pillars (reliability, security, cost optimization, operational
excellence, performance efficiency) run through every phase: requirements (non-functional
categories) → basic design (sections) → detailed design (per-resource settings) → tasks
(cross-cutting) → unit-test (pillar-labelled cases) → analyze (coverage matrix).

### Out of scope (future)

Deployment/operations design (what-if gate as CI gate, Deployment Stacks, OIDC, CI/CD pipelines)
is **not** included — this kit covers the SI phases up to unit testing. It is a candidate for a
future extension.

## Numbered phase layout (A2)

Core machine artifacts (`spec.md`, `plan.md`, `tasks.md`, …) stay at the feature root because
Spec Kit's scripts require fixed paths. The `100_` and `500_` folders therefore contain a
pointer `README.md` to the real file. `000_index.md` ties every phase together in order.

```text
specs/<feature>/
├── 000_index.md
├── spec.md  plan.md  tasks.md  (root, script-required)
├── 100_requirements/   (pointer -> ../spec.md)
├── 200_basic-design/   basic-design.md
├── 300_detail-design/  detail-design.md  (plan.md at root)
├── 400_test-design/    unit-test-spec.md
├── 500_tasks/          (pointer -> ../tasks.md) + analysis-report.md
├── 600_build/          *.bicep
└── 700_unit-test/      test-results.md
```

## Install

```bash
specify preset add --dev ./presets/bicep-si
specify extension add --dev ./extensions/bicep
```

## Full flow

```
/speckit.constitution → /speckit.specify → /speckit.clarify
→ /speckit.bicep.basic-design → /speckit.bicep.detail-design
→ /speckit.bicep.test-design  (review gate)
→ /speckit.tasks → /speckit.analyze
→ /speckit.implement → /speckit.bicep.test
```

## Maintenance note

Overrides use `append`, so core command updates flow through automatically; only the appended
addenda need occasional review for wording drift against upstream.
